# travel-guide 示例

## 轻量：半日玩吃

```text
用户：杭州半天，情侣，想人少一点，顺便吃饭。

行为：轻量档；crowd=人少；不问自驾/续航；不问 content_focus（默认都要）。
产出：一条可执行半日路线 + 避坑；不生成 HTML。
```

## 攻略：周末未说天数

```text
用户：周末去景德镇玩，做出行攻略。

行为：攻略档；天数默认 2；一次问卷补：出发地、是否自驾、侧重、人流、同行（已给的跳过）。
未答侧重→均衡；未答人流→适中；未答出发地→可定稿但标待补。
```

## 电车自驾

```text
用户：上海出发自驾去黄山 3 天，电车。

行为：必问续航 km；未给续航不定稿充电日程（可先搜）。
冬季出行：单段按续航×0.55～0.6；日程时间线含充电节点；HTML 填 EV 块。
```

## 偏美食 + 带老人

```text
用户：成都 4 日，偏吃，带父母。

行为：content_focus=偏美食；日程餐饮锚点优先；suitable_for 强调适老，避高强度徒步；摘要写「适合谁/不太适合谁」。
```

## 小红书不可用

```text
行为：公开搜索仍出 HTML + 摘要；摘要首段声明未用小红书及原因；不伪造笔记引用。
```

## 换肤

```text
生成默认 A 山野旅行 → 摘要询问是否改 B 海岸 / C 夜游
用户也可在 HTML 顶栏自行切换（localStorage 记住）。
改肤不必重跑小红书研究，只改 data-theme。
```
## 出发与返程不同

```text
罗城出发、行程结束于柳州 → 单程进城，末日不安排回罗城
未说返程终点 → 默认回到出发地（往返）
两端都空 → 大交通/跨城标待补
HTML 写「行程结束于柳州」，禁止写 return=柳州
```

## 路书与导航

```text
攻略档每个点：导航关键词 + 地址/地标 + 找店提示 + 可选高德搜索链接
每日顶部路书：A→B→C 顺序 + 段间车程/步行 + 停车一句
不确定门牌：写「导航搜店名，以门店为准」，不编造。
```

## 门票与预约（方案 B 深链）

```text
适用景点节点：.ticket-line = 状态 + 参考价（以出行时为准）+ 购票深链
深链优先级：官方预约页 > 携程/美团/飞猪票务页 > 平台关键词搜索页（1～2 个即可）
免票/无需预约：仍保留该行，写「免票 / 无需预约」
无可靠 URL：写「出行前于美团/携程搜店名」，禁止伪造商品 ID/短链
深链旁固定：链接可能失效，下单前核对景区名与日期
文末预约购票表加「购票链接」列，与节点一致
轻量档/工具短答：对话一句即可，不强制节点级
餐饮仅强烈建议预约时写；酒店/充电不写门票行
```

## 时长 · 重点 · 避堵 · 出片 · 雨备

```text
景点节点：.day-rail-row.tl-pair → 左主线 + 右 .spot-side（与今日亮点/重要提醒同一竖轨）
路书行：.day-rail-row.day-rail-meta（左路书，右亮点+提醒）；雨备 .day-rail-rain 全宽
重要提醒：默认展示 3 条，多的 tip-more 折叠（打印展开）
同日事实不三处复读（路线/时长/到点）
.photo-fold 默认折叠，打印展开
待办 / 预算：右侧抽屉 + float-dock「待办」「预算」；正文 .dock-jump 短链；打印展开全文
文风：短句、具体钟点；禁「值得一提/不容错过/完美结合」等套话
节假日：行前再核开放/夜场/局部封闭
电车：充电与午晚高峰错峰或写明先后
```

## 灵感来源

重要玩吃节点旁加「来源」行（小红书 explore 链或公开 URL）。
文末另加「攻略参考地址」：`<details class="refs-fold">` 默认收起，去重列出攻略/笔记链；不含高德、购票深链与图源。打印时临时展开。
无可靠链：写「综合公开渠道」；禁止伪造笔记 ID。

## 选点口径（评论核验）

主线：本地口碑、复访、值得停留。
网红：必看评论——共识好可进主线或出片折叠并写排队成本；差评多则降级/跳过。
出片机位尤其按评论核验，不因「网红」一刀切丢掉。
吃：居民区/菜市优先；步行街店须评论过关。

## 章节顺序

总览 → 每日行程（每卡 `.day-weather` + 路书；有雨则雨备）→ 预约与行前准备（`.prep-cluster`；待办/预算进抽屉，正文留短链）→ 适宜人群 → 实用建议 → 充电安排 → 攻略参考地址（折叠）→ 页脚。

## 每日天气与穿衣

有 `dates`：优先 Open-Meteo MCP（或 HTTP）；填气温/现象/降水 + 一句穿衣。
预报盖不住的日子写气候向，并标「出行前再核」。禁止假装精确到小时。

## 行前待办

携带清单、注意事项、预约准备用 checkbox（`.todo-item`）；`data-todo-key` + localStorage；显示已完成 x/y。
换设备/清缓存会丢勾选。

## 插图与路线总览

总览：`.route-overview` 日卡片（顶图，Day 徽章叠左上角 + 主题 + meta + 要点）；桌面用 `›` 分隔，禁止贯穿徽章的连线。
插图：总览每天尽量 1 张顶图；正文重要节点 `.media-figure`（整份建议 ≥ 天数+2）。
优先 `guides/<slug>/media/` 本地图（相对路径 `media/…`）→ Wikimedia/Openverse → 无图省略。
禁止热链/截图小红书原图；页脚 `.img-disclaimer` 固定免责。
图注须标图源（Wikimedia 链或「本地 media/… · 用户提供」）。

## PDF 与分享

攻略档：HTML/PDF 写入 `guides/<slug>/`（含 meta.json）；写完后无头浏览器打 PDF；页内「导出 PDF」= print。
push 后 Vercel（`web/`）首页与 `/g/<slug>` 自动更新。
手机：配色收入「配色」按钮；桌面展开 A/B/C。打印样式默认紧凑。
**国内发给同行：默认推 PDF（微信传文件）。**
要网页链接时：腾讯云静态托管 / 阿里云 OSS+CDN / Gitee Pages 优先；GitHub、Cloudflare Pages 备选并提醒可能打不开。无托管勿编造 URL。

## 粗规划闸门（默认）

攻略档默认先出粗规划卡（每日主题+点名），用户 OK 后再细化并出 HTML/PDF。
说「直接出完整攻略」可跳过。
